# 09_Data_Architecture

## 用途
ナレッジベース・AIシステムを支えるデータ構造の設計を置く場所。「知識をどう構造化し、どうシステムに載せるか」を扱う技術的なレイヤー。

## 格納するもの
- 各フォルダ（01〜06）のデータをDB/RAG基盤に落とし込む際のスキーマ設計
- ケースデータ・知識ベースのメタデータ設計（タグ体系、ID体系、関連付けのルール）
- ベクトルDB／検索基盤の構成、埋め込み対象・チャンク分割方針
- AIシステム全体のデータフロー（入力→処理→出力、各AI間のデータ受け渡し）
- 個人情報・機密情報の扱い方（アクセス権限、匿名化処理の設計）

## 他フォルダとの関係
01_Domain_Modelが「概念的な構造」であるのに対し、09は「それを実際にシステムでどう実装するか」という実装寄りの設計。07_Product_Strategyで決めた機能を実現するための技術基盤。

## 発展ステップとの関係
ケース対応AI・品質評価AIが個別に構築されるフェーズでは各AI用のデータ構造を、福祉現場OSへ発展する段階では複数AI・複数事業所をまたぐ統合データ基盤の設計をここに蓄積する。

## 運用ルール（叩き台）
- スキーマ変更時はバージョンを明記し、影響範囲（どのフォルダのデータに影響するか）を記録する
